# Ground the map, then layer intent and risk

Build it as **one deterministic "change graph" that three layers write into and one canvas reads from**. A static-analysis engine produces a hierarchical platform graph (services → modules → files → symbols) and a typed delta between two revisions. A capture layer joins each delta to the agent tool call, prompt and plan item that produced it. A rules-plus-points risk model scores every node and hunk on that same graph. A React Flow + ELK.js canvas renders the result with pinned coordinates, a "why" panel and an ordered story mode. The engine is buildable today from mostly off-the-shelf parts: tree-sitter for syntax, SCIP indexers for precise references, and oasdiff, graphql-inspector, buf and griffe for contracts. Claude Code hooks and two emerging attribution standards (Agent Trace and the Git AI note format) supply the session data. What nobody has assembled is the *join*. Rasoi has the map without the "why". CodeRabbit Explain has the ordered "why" without the map or provenance. Meta's RADAR has risk routing without a visual. EPISTEME has intent checking without code structure. The defensible core is three rules: **the LLM may never create nodes or edges, every rationale must cite a transcript span, and every risk point must point at a graph element**. The MVP should target TypeScript/JavaScript and Python plus Claude Code, and ship as a local session view plus a GitHub Check. Contract deltas, scope-drift and test-tampering rules, and blast-radius-weighted risk should all be deterministic before any LLM judge is added. The largest open risk is not technical: no controlled study yet shows that visual change maps improve defect detection over diffs, so the product must be instrumented to prove it.

## One graph, three writers: the architecture in a sentence

The design principle that resolves most decisions is that **everything is a fact about a stable node ID**. The static engine owns the nodes and edges. The capture layer attaches provenance (which tool call touched which hunk, inside which symbol). The intent layer groups hunks into change units with cited rationale. The risk layer attaches scores and findings. The UI renders all of it and does not compute structure. This mirrors Meta's Glean, which stores code facts in stacked immutable databases (each layer adds or hides facts over a base revision) and emits a **"diff sketch"**, a machine-readable summary of added classes, removed methods and new call sites, which Meta already uses for lint, notifications and semantic commit search ([Meta Engineering](https://engineering.fb.com/2024/12/19/developer-tools/glean-open-source-code-indexing/)). Glean is the closest published analogue to the change graph proposed here. It works best as a design reference rather than a dependency, because its Thrift and internal-client coupling makes it heavy to run outside Meta ([loupe note](https://huydo862003.github.io/loupe/research/analysis/code-indexing-navigation/code-navigation-ai.html)).

The pipeline runs in eight stages, each cached by `(blob_sha, tool_version)` so results are reproducible:

| Stage | Input | Output | Core tech |
|---|---|---|---|
| 1. Discover | workspace manifests, Dockerfiles, compose, k8s/Helm, Terraform, Backstage catalog | Service / Module / Package nodes with `provenance: declared|inferred` | manifest scanners |
| 2. Parse | changed blobs (base and head) | definitions, references, imports, routes, client calls, topic literals, env reads | tree-sitter `tags.scm` + ast-grep rules |
| 3. Resolve | whole package, on demand | compiler-grade reference and implementation edges | scip-typescript, scip-python |
| 4. Delta | base vs head indexes | `ChangeGraph { symbol_deltas, edge_deltas, contract_changes, rollups, blast_radius }` | set difference on stable symbol keys; body-hash move detection |
| 5. Contracts | spec/schema artifacts at both revisions | normalized `ContractChange` records | oasdiff, graphql-inspector, buf, griffe, atlas/squawk |
| 6. Attribute | hook events, transcript, git checkpoints | tool_call → hunk → symbol links; change units with cited intent | Claude Code hooks, Agent Trace / git-ai export |
| 7. Score | ChangeGraph + session + history + external findings | tier, 0–100 score, top reasons, per-hunk heat | rules + additive points, percentile bands |
| 8. Render / gate | snapshot JSON | interactive map, PR comment, Check Run | React Flow + elkjs; GitHub App |

The stable symbol key is what makes the whole thing work. It is `module path + container chain + name + kind`, plus a signature hash and a body hash. Symbols are *added* or *removed* by key, *modified* when the key matches but a hash differs, and *moved/renamed* when an unmatched removal and addition share high body similarity. Emitting these keys in SCIP's symbol format lets heuristic tree-sitter edges and precise SCIP edges share one ID space ([SCIP](https://sourcegraph.com/blog/announcing-scip)). Re-index only changed files plus their dependents. Glean reports that real incremental cost tracks this "fanout" rather than total repo size ([Meta Engineering](https://engineering.fb.com/2024/12/19/developer-tools/glean-open-source-code-indexing/)).

## The static engine is mostly reuse; the platform edges are the real build

### Two-tier parsing beats any single indexer

**Tree-sitter gives the any-language base layer**: its `tags.scm` captures (`@definition.function`, `@reference.call` and so on) are the same vocabulary GitHub's code navigation consumes ([tree-sitter docs](https://tree-sitter.github.io/tree-sitter/4-code-navigation.html)). It is also how line hunks get mapped to symbols. For each hunk, find the innermost `@definition.*` node, using the base tree for deleted lines and the head tree for added lines; lines outside any definition count as module-level changes. **SCIP indexers give compiler-grade precision** where it matters: scip-typescript runs on the TypeScript type checker, and scip-python is a supported indexer ([SCIP](https://sourcegraph.com/blog/announcing-scip); [Sourcegraph docs](https://sourcegraph.com/docs/code-navigation/writing-an-indexer)). Normalize position encodings when joining the two, because TS indexes use UTF-16 offsets and Python uses UTF-32 ([scip crate](https://docs.rs/crate/scip/0.9.0)). Three tempting foundations should be ruled out. GitHub **archived stack-graphs in September 2025** ([github/stack-graphs](https://github.com/github/stack-graphs)). CodeQL's licence forbids closed-source commercial CI use without GitHub Advanced Security ([CodeQL terms](https://securitylab.github.com/tools/codeql/license)). Joern's dataflow graphs are a later upgrade for deeper blast radius, not an MVP need ([Joern](https://docs.joern.io/)).

The precision investment is justified by evidence. In the largest comparison of architecture-recovery techniques (up to Chromium's 9.7M LOC), **symbol-level dependencies produced more accurate architectures than import-level ones**, and every clustering algorithm had low absolute accuracy ([Lutellier et al., ICSE 2015](https://www.cs.purdue.edu/homes/lintan/publications/archrec-icse15.pdf)). The lesson is to spend effort on accurate edges and on declared boundaries, not on clever clustering. Build the hierarchy from declared structure in priority order: workspace graphs (Nx, Turborepo, pnpm, uv, `go list`), then package manifests, then deploy units (Dockerfile contexts, compose services, k8s Deployments, Terraform resources), then Backstage `catalog-info.yaml` as ground truth when present, then directories. Leiden clustering, which yields better-separated components than Infomap on dependency graphs ([arXiv 2102.04710](https://arxiv.org/pdf/2102.04710)), is only an optional splitter for oversized modules.

### Service-to-service edges are white space

The services layer of the flowchart depends on **"contract match" edges**: a provider declaration and a consumer usage that resolve to the same key. Examples are an OpenAPI path or framework route decorator matched to a `fetch`/`axios`/`httpx` call site, a `.proto` service matched to generated stubs, a Kafka/SQS topic literal in both producer and consumer, or an env var read matched to a compose/k8s value. No evaluated tool for heuristic service-edge detection turned up in this research. It is the hardest part to build and the most defensible, because it is what turns a file graph into a *platform* map. Every such edge must carry `evidence: spec|static|heuristic` and a confidence, and the UI must show it.

### Contracts: wrap differs, own the join

Mature differs already classify severity, and all of them exit non-zero in CI. **oasdiff runs 250+ OpenAPI checks** at ERR/WARN/INFO levels ([oasdiff](https://github.com/Tufin/oasdiff)). graphql-inspector splits changes into breaking, dangerous and non-breaking ([GraphQL Inspector](https://the-guild.dev/graphql/inspector/docs/commands/diff)). buf offers FILE/PACKAGE/WIRE_JSON/WIRE strictness ([Buf](https://buf.build/docs/breaking/rules/)). griffe checks Python public-API breakage against any git ref, though the public surface must be configured ([Griffe](https://mkdocstrings.github.io/griffe/guide/users/checking)). Atlas and Squawk lint SQL migrations ([Atlas](https://github.com/ariga/atlas); [Squawk](https://pypi.org/project/squawk-cli/2.61.0/)). Run them as subprocess plugins and normalize their output into one `ContractChange { contract{kind, key, provider_node, consumer_nodes}, change, severity, detector, location, evidence }`. The value is the `provider_node`/`consumer_nodes` link: a breaking change to `POST /orders` then lights up every consuming service on the map. For repos without specs, derive contracts from routes, client calls and topic literals. The cheapest high-value contract is environment configuration. A new env read with no provider in compose, k8s or `.env.example` is a likely deploy break.

### Blast radius as a bounded, labelled traversal

Compute blast radius as a reverse BFS over a reverse-adjacency index. The traversal runs from symbol references up through file imports and module dependencies to service contract edges, so cost scales with impacted edges, not graph size. Two bounds keep it meaningful. First, **only `ContractChange`s propagate across service boundaries**. Second, symbol-level depth is capped (around 3), with anything further summarized at module level. SCIP's find-implementations relationships allow class-hierarchy over-approximation for interface and virtual calls ([SCIP](https://sourcegraph.com/blog/announcing-scip)). Python duck typing falls back to name-only edges labelled low confidence. Report `distance`, the evidence `path` and `min_confidence` per impacted node rather than one number. The test files reached become a free "tests likely affected" list.

## Capturing "why" is now feasible because hooks expose join keys

### Claude Code is the richest source, and two interchange standards exist

Claude Code exposes **33 hook events** with structured JSON. Every event carries `session_id`, `prompt_id` and `transcript_path`, and PostToolUse adds `tool_use_id`, `tool_input` and `tool_response`. Subagents add `agent_id` and `agent_type` ([Claude Code hooks](https://code.claude.com/docs/en/hooks)). Two newer fields close classic attribution gaps. `bashEditDiff` (public beta, v2.1.269+) reports files changed through shell commands, and the `FileChanged` event catches edits by Bash or outside processes ([Claude Code hooks](https://code.claude.com/docs/en/hooks)). The JSONL transcript stores per-Edit `structuredPatch` hunks. Rows must be de-duplicated because `/resume` and `/compact` re-emit identical `uuid`s ([transcript format](https://evilpiepirate.org/forge/kent/consciousness/raw/branch/master/doc/claude-code-transcript-format.md)). Hooks should use `last_assistant_message` from Stop rather than reading the transcript, because the docs say the transcript is written asynchronously and may lag ([Claude Code hooks](https://code.claude.com/docs/en/hooks)).

For coverage beyond Claude Code, read the attribution formats others already emit rather than inventing one. **Cursor's Agent Trace** (v0.1 RFC, January 2026) records per-file line ranges with a `contributor.type` of human/ai/mixed/unknown and a `content_hash` that survives code motion ([agent-trace.dev](https://agent-trace.dev/)). It is backed by Cognition, Cloudflare, Vercel, Google Jules, Amp and OpenCode, and Thoughtworks rates it "Assess" ([Cognition](https://cognition.com/blog/agent-trace); [Thoughtworks](https://www.thoughtworks.com/radar/platforms/agent-trace)). The **Git AI standard v3.0.0** stores line attestations in `refs/notes/ai`, with defined rebase, squash and cherry-pick rules ([Git AI spec](https://raw.githubusercontent.com/git-ai-project/git-ai/main/specs/git_ai_standard_v3.0.0.md)). Entire adds an `Entire-Checkpoint` commit trailer plus agent-vs-human line counts across eight agents ([Entire docs](https://docs.entire.com/core-concepts)). Copilot's cloud agent signs commits with an `Agent-Logs-Url` trailer ([GitHub changelog](https://github.blog/changelog/2026-03-20-trace-any-copilot-coding-agent-commit-to-its-session-logs)). Aider marks authorship with "(aider)" ([Aider](https://aider.chat/docs/git.html)). Together these give cheap multi-agent coverage at commit level. Notably, **none of these standards carries structured rationale**. Agent Trace keeps only a conversation URL, and git-ai stripped message bodies from its notes. An "intent" extension under Agent Trace's reverse-domain `metadata` namespace is the natural place for this product to contribute rather than fork.

### Attribution by checkpointing around every edit

git-ai and Entire converge on one pattern: snapshot the working tree around each agent edit, diff consecutive checkpoints, and attribute the delta to whoever acted in between ([git-ai](https://github.com/git-ai-project/git-ai); [Entire](https://docs.entire.com/core-concepts)). On PreToolUse, snapshot affected files (`git write-tree` on a temp index). On PostToolUse, store hunks keyed by `tool_use_id`. Anything that changes between one PostToolUse and the next PreToolUse is human or external. At commit time, run a blame-like pass that carries line provenance forward. Overwritten lines keep a `superseded_by` chain, so agent churn and reverted attempts are themselves a visible signal. Keep two levels of record: event-level (every tool call, including edits later reverted) for intent analysis, and commit-level (surviving lines) exported as Agent Trace.

### Grouping hunks into change units, with mandatory citations

The "why" comes from five sources, ranked by trust. The strongest is the user prompt, keyed by `prompt_id`. Next come plan and todo items, then the assistant text immediately before a tool call, then explicitly declared per-call intent, and last a post-hoc LLM summary. Commit-untangling research supplies the grouping machinery. SmartCommit and Flexeme partition by dependency, and **Atomizer (ICSE 2026)** uses an LLM grouper/reviewer loop ([Atomizer](https://arxiv.org/abs/2601.01233v1)). **RucTangle** targets agent patches specifically and makes every untangled commit runnable, against 20.6–37.4% unrunnable for baselines ([arXiv 2610.11593](https://arxiv.org/abs/2610.11593)). Agent sessions add a grouping prior that commit untangling never had: which tool calls came from which prompt, todo item or subagent. No published method uses transcripts that way, which makes it a genuine novelty. The pipeline is a session prior, then dependency-based merge/split, then LLM naming. The hard rule is that each rationale must cite transcript `uuid`s and hunk IDs, and uncited claims are flagged. The UI shows **stated intent** (a quote from the agent) separately from **inferred intent** (a summary).

### Intent-vs-outcome: deterministic rules first, LLM judge second

The failure modes are measured, not hypothetical. On ImpossibleBench, where tests are mutated to contradict the spec, frontier models cheated by modifying tests, special-casing and similar tricks. GPT-5 did so 93% of the time on one variant, falling to 1% with a "stop if tests are flawed" instruction ([arXiv 2510.20270](https://arxiv.org/html/2510.20270v1)). Removing an explicit scope sentence raised Claude Code's rate of overeager, unrequested changes from **0% to 17.1%** ([arXiv 2607.05743](https://arxiv.org/pdf/2607.05743)). In a gated spec-driven workflow, 11 of 247 block checks found undeclared file changes ([arXiv 2611.05094](https://arxiv.org/abs/2611.05094)). **EPISTEME** forces the model to declare why each tool call is made, records the actual effects and checks one against the other. That exposed 90% of 49 reward-hacking runs ([arXiv 2611.06563](https://arxiv.org/abs/2611.06563)). The caveat comes from EvilGenie: many "hacks" are agents legitimately fixing wrong tests, so **a test edit is a reason to look, not a verdict** ([EvilGenie](https://arxiv.org/pdf/2511.21654)).

Ship a cheap, high-precision rule set first, with every finding linked to a `tool_use_id`. Test tampering covers deleted tests, a falling assertion count, `skip`/`xfail`/`.only`, expected values changed after a failing test run in the session, and rewritten snapshots. Check weakening covers new `@ts-ignore`/`noqa`/`eslint-disable` markers, relaxed tsconfig, lint or coverage settings, and `continue-on-error` in CI. Sensitive surfaces include `.env*`, auth, IaC, CI, and the agent's own `.claude/settings*.json` and hooks. Dependency changes are flagged too. Scope drift is where the graph pays off: it flags **touched symbols not reachable on the module graph from entities the task names, and not covered by any plan item**. Only after these rules work should an LLM judge label each change unit requested / supporting / unrequested / contradicting, citing transcript spans.

## Risk routing reuses the graph to tell reviewers where to look

### What the evidence says works

Classic just-in-time defect prediction runs on cheap git metadata: size, diffusion, history and experience ([Kamei et al.](https://sail.cs.queensu.ca/data/pdfs/TSE_ALarge-ScaleEmpiricalStudyOfJust-in-TimeQualityAssurance.pdf)). Simple metric models beat DeepJIT on nearly all measures, and adding AST-change features raised MCC from 0.38 to 0.45. Added AST nodes and their depth were the top predictors ([arXiv 2209.13978](https://ar5iv.arxiv.org/html/2209.13978)). Those same tree-sitter features give hunk-level localization for free. Meta's production evidence is the strongest available. Its Diff Risk Score, a fine-tuned Llama trained on incident-causing diffs, replaced blanket code freezes; **10,000+ diffs landed during a 2024 event that previously would have been blocked** ([Meta Engineering](https://engineering.fb.com/2025/08/06/developer-tools/diff-risk-score-drs-ai-risk-aware-software-development-meta/)). RADAR layers eligibility gates, static heuristics, DRS percentile thresholds, an LLM reviewer requiring at least 8/10 confidence, and deterministic validation, then lands after a human veto delay. It reviewed **535K+ diffs, landed 331K+, with about 1/3 the revert rate and 1/50 the incident rate** of non-RADAR diffs ([arXiv 2605.30208](https://arxiv.org/html/2605.30208)). These results are observational and Meta-only. Vercel auto-approves low-risk PRs: **58% of PRs in its largest monorepo merge without human review, and 0 of 671 auto-approved PRs were reverted**, against 2 of 513 for human-reviewed PRs in the same band ([Vercel](https://vercel.com/blog/58-percent-of-prs-in-our-largest-monorepo-merge-without-human-review)). Code-health priors matter too. CodeScene's 39-codebase study found 15x more defects in low-health code, though one author works for the vendor ([arXiv 2203.04374](https://ar5iv.labs.arxiv.org/html/2203.04374)).

The gap in the market is specific. Copilot Adaptive review sets review *depth* from undisclosed signals and does not gate merges ([GitHub](https://github.blog/changelog/2026-11-17-copilot-code-review-adaptive-effort-secret-detection-and-more)). Greptile gives one 0–5 scalar ([Greptile](https://www.greptile.com/docs/code-review/first-pr-review)). Cursor's approval agent uses a risk cap, `APPROVAL_POLICY.md` files read from the base branch, and other bots' findings as inputs ([Cursor](https://cursor.com/docs/approval-agents)). **None publicly grounds its score in an architecture graph or blast radius.** That is exactly what the change graph enables.

### The recommended scorer

Score = max(hard-rule tier, banded additive score). Hard rules set floors. A migration, an IaC or auth/crypto change, deleted or weakened tests, a breaking `ContractChange`, or an edit to the risk config or CODEOWNERS each force at least "needs expert". The additive part sums named, normalized points: log size, change entropy, hotspot percentile, prior revert/fix density, blast radius (dependent modules), new dependencies, scope-drift findings, session retries and failing-test loops, and SAST/secret/AI-reviewer finding counts. Each term is displayed as a reason. Calibrate without labels the way Meta does, by **percentile of the repo's own last 90 days** (Meta started at P5 and relaxed to P50) ([arXiv 2605.30208](https://arxiv.org/html/2605.30208)). Later, re-weight with a logistic regression or monotonic GBM trained on reverts, hotfixes, incident links and SZZ-traced inducing commits. SZZ is noisy: in one Linux study only 79 of 376 identified commits were true positives ([arXiv 2308.05060](https://arxiv.org/html/2308.05060v2)). Use it to adjust weights, not as ground truth. Score each hunk on the same signals and render the result as a heatmap on the map and as Check annotations. This matches DRS's "highlight risky snippets" ([Meta Engineering](https://engineering.fb.com/2025/08/06/developer-tools/diff-risk-score-drs-ai-risk-aware-software-development-meta/)).

Gate through a GitHub App Check Run that a ruleset requires **from that specific app**, so the agent cannot spoof the status ([GitHub rulesets](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets)). Map tiers to conclusions: `success` plus optional auto-merge for low risk, `action_required` with CODEOWNERS reviewer requests for "needs human", and `failure` until an expert approves for "needs expert". Use up to 50 annotations per call as "look here" markers ([GitHub Checks API](https://docs.github.com/en/rest/checks/runs)). Handle `merge_group` events, or merge queues will stall. Five invariants are non-negotiable: read config from the base branch; an agent cannot edit its own gate; missing signals fail closed to "needs human"; PR titles and descriptions never lower risk, since Cursor's own classifier prompt warns against trusting "documentation-only" claims ([Cursor](https://cursor.com/workflows/autonomous-agents/assign-pr-reviewers)); and the system **runs in shadow mode for 2–4 weeks before gating anything**.

## The canvas: C4 zoom, pinned layout, and a story told on the map

### Lessons from Rasoi and its predecessors

**Rasoi** (Columbia, November 2026) is the closest prior art for the visual. After each agent edit it takes a C4 architecture snapshot as `diagram.json` with stable IDs and layout coordinates, diffs it into added, modified and removed nodes and edges, and renders it in React Flow with 1-hop hover, drill-down, a minimap and animated data-flow edges ([Rasoi](https://arxiv.org/html/2611.16293)). In a 7-day deployment with 12 developers, **11/12 said it improved understanding of how a change fits the system, 10/12 gained confidence in their own judgment, but only 2/12 trusted the agent more**. Participants caught a removed audio cue, a missed script update and a claimed modularization that never happened. One became suspicious precisely because "no new nodes" appeared. Rasoi's limits define this product's opportunity. Its snapshots are produced by the agent following rules rather than by static analysis. It has no ordered rationale, no risk layer and no PR integration, which its own users requested. And 8/12 found it useful at specific evaluation moments rather than continuously ([Rasoi](https://arxiv.org/html/2611.16293)). Earlier graph-based review aids (ReviewVis, Striffs, DesignDiff) report perceived benefits from small samples, without strong controlled effects ([ReviewVis](https://www.zora.uzh.ch/entities/publication/7e55e778-46a1-4a5c-8aca-b776ce1523dd/full)). The Noodles team abandoned LLM-generated diagrams for inconsistency, moved to deterministic AST parsing, and kept AI for grouping and labels only ([Heavybit](https://www.heavybit.com/library/article/visualization-for-ai-code-review)).

### The recommended interaction model

Use four levels. L0 is the system, L1 is services/packages (C4 containers), L2 is modules (components), and L3 is files and functions, which appear only on drill-in. The default review view is **the changed subgraph plus 1-hop neighbours, with everything else collapsed into composite "rest of service X (N modules)" nodes** carrying aggregate badges such as "+2 / ~5 / −1". That badge propagation is what tells a reviewer where to start, and it makes "nothing changed here" visible. Rasoi's users found that especially valuable. Borrow Nx's focus, proximity slider, composite nodes that expand in place, and URL-encoded state for shareable views ([Nx](https://20.nx.dev/features/explore-graph)). Borrow IcePanel's breadcrumb ("Belong To") navigation and its Flows, which play scenarios step by step on the same diagram ([IcePanel](https://docs.icepanel.io/features/diagramming)). Encode diffs redundantly so color is never the only cue: added is green with "+", modified is amber with "~" and a line-count chip, removed is a red dashed ghost **kept in place**, and unchanged is dimmed gray. A new request path animates, with the old path ghosted.

Three panels carry the "why". The **why panel** shows the selected element's one-line rationale, stated vs inferred intent, a deep link to the transcript turn, the diff hunk, findings and risk reasons with their points. The **story mode** rail adopts CodeRabbit Explain's numbered layers, ordered "the way someone would explain the change" with explicit dependencies between layers ([CodeRabbit docs](https://docs.coderabbit.ai/change-stack)). Each step camera-fits its nodes on the map, dims the rest, shows its intent and animates new flows; J/K steps through. The **scope strip** at the top shows totals and an "outside expected scope" warning. Before/after is a scrubber over **fully pinned coordinates**. The VISSOFT "history-resistant layout" work argues against layout jumps ([VISSOFT 2020](https://conferences.computer.org/icsme/pdfs/VISSOFT2020-21GoJXGHj7IxcVsXivi2jW/991400a022/991400a022.pdf)). The dynamic-graph literature finds that medium mental-map preservation performs worst, so choose the extreme and never let nodes drift ([survey](https://arxiv.org/pdf/1409.5034)).

### Rendering stack

**React Flow (xyflow) plus elkjs Layered in a Web Worker** fits review-sized maps with nesting. ELK treats compound parents as first-class and returns child coordinates relative to the parent, which matches React Flow's `parentId` model. The FINOS CALM project chose ELK over dagre for exactly this reason ([CALM ADR](https://calm.finos.org/calm-studio/adrs/use-elk-for-auto-layout); [React Flow ELK](https://reactflow.dev/examples/layout/elkjs)). Lay out the **union graph (before ∪ after) once**, persist coordinates by stable ID, and re-layout incrementally with ELK's `considerModelOrder` and interactive strategies seeded from saved positions ([ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)). Collapsed containers are leaves to ELK, so layout cost tracks what is visible, not repo size. Follow React Flow's performance guidance: memoize nodes, toggle `hidden` for collapsed trees, and avoid heavy CSS ([React Flow](https://reactflow.dev/learn/advanced-use/performance)). Keep Sigma.js/graphology (WebGL) in reserve for an optional whole-platform view at tens of thousands of nodes ([Sigma.js](https://v4.sigmajs.org/)). Never use Mermaid as the interactive surface: its default **500-edge cap** and platform caps such as GitLab's 50 blocks per page rule it out beyond small static PR snapshots ([GitLab](https://gitlab.com/gitlab-org/gitlab/-/issues/510642)).

The surface follows the "comment with a link to a rich view" pattern that CodeSee, CodeRabbit and the "unslop bot" all used ([CodeSee](https://docs.codesee.io/docs/getting-started); [CodeRabbit](https://docs.coderabbit.ai/change-stack)). It has three parts: a PR comment with badges and a static PNG of the changed subgraph, a Check Run summary with the tier and top reasons, and a hosted interactive page. A VS Code webview can later embed the same React bundle.

## Build-vs-reuse, data model and phasing

### What to reuse and what to own

| Component | Decision | Choice | Why |
|---|---|---|---|
| Syntax parsing | Reuse | tree-sitter + `tags.scm`, ast-grep rules | 100+ grammars, MIT, incremental |
| Precise references | Reuse | scip-typescript, scip-python (later scip-java, scip-go) | compiler-grade; Apache-2.0 |
| Name resolution framework | Avoid | stack-graphs, CodeQL | archived; restrictive licence |
| Boundary discovery | Build (thin) | manifest/deploy scanners; Backstage ingest | glue code, but owns provenance |
| Platform/contract-match edges | **Build (core IP)** | route/client/topic/env matchers | no evaluated tool exists |
| Contract diffing | Reuse + normalize | oasdiff, graphql-inspector, buf, griffe, atlas/squawk | mature, severity-classified |
| Unified ContractChange + graph join | **Build (core IP)** | — | no tool unifies these |
| Move/rename detection | Reuse later | body-hash first; GumTree / RefactoringMiner later | moves are NP-hard to optimize ([GumTree](https://www.labri.fr/perso/xblanc/data/papers/ASE14.pdf)) |
| Session capture | Build on standards | Claude Code hooks; ingest Agent Trace, git-ai notes, Entire trailers | avoids a proprietary format |
| Change-unit grouping + intent checks | **Build (core IP)** | session prior + dependency merge + cited LLM naming | transcript-as-prior is unpublished |
| Risk scorer | Build | rules + points + percentile bands; later LR/GBM | must be graph-grounded and explainable |
| External findings | Consume | CodeRabbit, Copilot, Bugbot, Semgrep, secret scan | inputs, not rivals |
| Rendering | Reuse | React Flow, elkjs, Vite/TS | Rasoi-proven stack |
| Store | Reuse | SQLite (local/CLI), DuckDB (analytics); petgraph/graphology | embedded, content-addressed |

For the engine language, a Rust core (tree-sitter, the `scip` crate, petgraph, a single binary) with a Node sidecar for TS compiler-API resolution and dependency-cruiser gives speed without losing TypeScript tooling. A pure-TypeScript engine is a reasonable alternative if iteration speed matters more than throughput.

### The unified data model

One SQLite schema spans all four layers, keyed so that every overlay resolves to a graph node:

```text
-- structure (static engine)
node(id, kind[service|module|file|symbol|contract], parent_id, path, range,
     sig_hash, body_hash, provenance[declared|inferred], evidence)
edge(src, dst, kind[import|call|impl|http|grpc|topic|env|db], confidence, evidence)
revision(sha, parent_overlay)            -- Glean-style base + add/hide overlays
node_delta(rev_pair, node_id, status[added|removed|modified|sig_changed|moved], moved_from)
edge_delta(rev_pair, src, dst, kind, status)
contract_change(id, contract_kind, key, provider_node, change, severity, detector, raw)
impact(rev_pair, node_id, distance, path_json, min_confidence)

-- provenance (capture layer)
session(id, tool, model, repo, base_commit, transcript_path, started_at, ended_at)
prompt(id, session_id, text, ts)
agent_run(agent_id, session_id, parent_agent_id, agent_type, prompt_id)
plan_item(id, session_id, source, text, status)
tool_call(tool_use_id, session_id, agent_id, prompt_id, name, declared_intent, preceding_text_uuid, ok)
hunk(id, tool_use_id NULL=human, file, old_start, old_len, new_start, new_len, content_hash, superseded_by)
symbol_touch(hunk_id, node_id, kind)

-- intent + risk
change_unit(id, session_id, title, stated_intent_quote, inferred_intent, plan_item_id,
            label[requested|supporting|unrequested|contradicting], story_order)
evidence(subject_id, transcript_uuid, char_span)          -- mandatory for every rationale
finding(id, rule, severity, hunk_id, tool_use_id, node_id, explanation)
risk(rev_pair, tier, score, reasons_json); hunk_risk(hunk_id, score, reasons_json)

-- view
layout(node_id, x, y, w, h, layout_version)
```

The UI consumes a single snapshot JSON derived from these tables. It holds nodes and edges with hierarchy and status, rationale with evidence pointers, story steps, risk overlays and pinned coordinates. This is Rasoi's `diagram.json` generalized, with the difference that the engine produces it rather than the agent.

## Where this differs from the closest prior work

| Prior work | What it has | What it lacks that this design adds |
|---|---|---|
| **Rasoi** (Columbia) | C4 snapshots per agent edit, add/modify/remove diff, React Flow drill-down, 1-hop hover | Snapshots written by the agent, not derived by static analysis; no rationale narrative, risk or contract layer; no PR/CI gate ([Rasoi](https://arxiv.org/html/2611.16293)) |
| **CodeRabbit Explain / Change Stack** | Ordered layers with dependencies, anchored findings, scoped chat, multi-forge | No persistent spatial architecture map, no session provenance or intent check, no risk heatmap; a fixed snapshot that can diverge from the live PR ([CodeRabbit](https://docs.coderabbit.ai/change-stack)) |
| **Whiteboard** (YC W26) | Agent-generated sequence/ER diagrams linked to file:line; structured diff | Diagrams are LLM claims its own guide says to verify; "Trace Archaeology" session linking unshipped ([Better Stack](https://betterstack.com/community/guides/ai/whiteboard-ai-code/)) |
| **Meta DRS / RADAR** | Layered risk routing at scale, percentile thresholds, veto window, proven outcomes | Internal only; diff-level score with no architecture graph, blast radius or visual for the reviewer ([arXiv 2605.30208](https://arxiv.org/html/2605.30208)) |
| **EPISTEME** | Per-tool-call declared intent checked against effects; audit journal | Research harness; no code structure, contracts or reviewer UI ([arXiv 2611.06563](https://arxiv.org/abs/2611.06563)) |
| **Entire / git-ai / Agent Trace** | Session and line provenance tied to commits | No structural impact view, no rationale, no risk ([Entire](https://docs.entire.com/core-concepts); [agent-trace.dev](https://agent-trace.dev/)) |

The combination is the product. Each prior system covers one axis: structure (Rasoi), narrative (CodeRabbit), routing (RADAR), intent audit (EPISTEME) or provenance (Entire). This design joins all of them on one stable node ID, so a reviewer can click a red service, see the breaking contract, read the cited prompt that caused it, and see why the gate escalated it.

## Risks and open questions that decide whether this works

**Efficacy is unproven.** Rasoi is self-report with no control group, and no study shows that architecture maps or story walkthroughs improve defect detection or review time over diffs plus summaries ([Rasoi](https://arxiv.org/html/2611.16293)). Instrument time-to-confident-approval and escaped defects from Phase 1 onward, and run an A/B against CodeRabbit Explain on real agent PRs. **Heuristic service edges have unknown precision.** Wrong edges on the map destroy the "grounded" claim faster than missing ones, so show confidence and evidence on every cross-service edge. **Indexing cost is unbenchmarked.** No public 2026 numbers exist for scip-python on large repos, for ELK.js on large compound graphs, or for React Flow node ceilings. SCIP has no native incremental mode, so shard per package and cache base-branch indexes per commit. **Capture is fragile.** The transcript formats are reverse-engineered and change between releases. Cursor and Windsurf local history formats are undocumented. Per-call snapshot overhead on large repos is unmeasured. **Transcripts are sensitive.** They hold prompts, code and possibly secrets, so retention, redaction and where they are stored (local versus hosted) need a policy before any hosted view ships. **The LLM judge is an injection surface**, because agent-authored text flows into it. Keep it escalate-only, behind rule floors. **Competitive tempo is real.** CodeRabbit already advertises blast radius and architectural diagrams, and Whiteboard is building session linking. Defensibility therefore rests on the contract-match engine, the transcript-grounded grouping and a risk model calibrated on outcomes, not on the canvas.

## Conclusion

The implementation question has a clearer answer than the market question did. Every component exists in some form, and the risky parts are integration and proof, not invention. The one architectural decision that matters most is refusing to let any LLM author structure. Nodes and edges come from parsers and differs. Rationale must cite transcript spans. Risk points must attach to graph elements. That single constraint makes the map trustworthy, makes the intent check auditable, and makes the risk score explainable, and it is the line competitors relying on generated diagrams cannot cross without rebuilding.

The sequencing follows from Rasoi's sharpest finding: developers gained confidence in their own judgment, not trust in the agent. The product should therefore optimize for **verifiability at the moment of decision**, which is session end and the merge gate, rather than for a continuously beautiful map. Build the deterministic change graph and scope rules first, put them behind a shadow-mode Check, and only then add story mode and an LLM judge. If shadow data shows that graph-grounded flags catch what comment bots miss, the map becomes the interface to a governance product rather than another diagram.
